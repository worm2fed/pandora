# 0001. SQLite flow journal, artifacts stay content authority

> Shipgate records operational state as append-only events in a per-project, gitignored
> SQLite database driven by a stdlib-only Python CLI; markdown artifacts remain the
> authority for content. Capture is enforced by hooks and script gates, not requested
> by prose. No event-store server.

## Context

Shipgate's state is 100% inferred (phase from artifact shape, watcher from a
snapshot-overwrite file) and its history is ephemeral (gate decisions, verify evidence).
An evaluation of KurrentDB (2026-08-20) confirmed the *pattern* — append-only streams,
expected-version conditional append, replayable history — fixes exactly these gaps, but
the *server* is disqualifying for a distributed plugin: users would have to run a ~1 GiB
service (ARM64 images still experimental, manual scavenge on the free tier, non-OSI
license) for two primitives SQLite reproduces in a few lines. Three linked forks had to
be settled: storage engine, authority split, and script runtime.

## Decision

(1) **SQLite, embedded, no server** — one `events` table with `UNIQUE(stream, version)`
as the conditional-append primitive, WAL mode for multi-session use on one machine.
(2) **Journal = operational state; artifacts = content.** PRD/ADR/worklog files stay the
human-readable source of truth for *what* was specified/decided/planned; the journal is
the source of truth for *where the flow stands and what happened* (phases, gate
decisions, verify evidence, watcher observations). Events carry artifact paths, never
document bodies. On disagreement, artifacts win for content, journal for position, and
the discrepancy is surfaced, not silently resolved.
(3) **Python 3 stdlib CLI** (`scripts/journal.py`) as the only write/read path — no
dependencies to install, callable from any skill via Bash, testable standalone.
(4) **Capture is enforced, not requested.** On journaled projects the journal is the
sole routing source, so a missed append manifests as a stuck flow at the next routing
decision — never as silent drift. A plugin hook layer auto-records artifact writes,
injects the resume brief at session start, and blocks session end when semantic events
are missing against observed changes; `journal.py` itself refuses invalid gate
transitions (audited `--force` override only). Hooks read a machine-readable sidecar
(`.claude/shipgate.json`, generated by `setup`) since they cannot parse prose config.

## Alternatives considered

- **KurrentDB (or NATS JetStream/Postgres)** — the real thing; rejected: any server
  dependency is disqualifying for a plugin users install from a marketplace. JetStream
  noted as the answer *if* a push/queue need ever appears — none exists here.
- **JSONL files** — zero-dependency and append-only, but no conditional append, no
  indexed reads for `status`, and concurrent-writer atomicity depends on line length;
  SQLite costs nothing more and removes all three caveats. JSONL survives as the
  export/import format.
- **Journal as single source of truth (artifacts derived)** — cleaner event-sourcing
  doctrine, but artifacts must stay human-editable and git/vault-portable across
  machines; making them projections would break editing and multi-machine work.
- **Node/shell script layer** — Node needs `better-sqlite3` (native build); shell +
  `sqlite3` CLI is not reliably present and quoting JSON in shell is a bug farm.
  Python 3 + stdlib `sqlite3` is present on every target platform.
- **Prose-only (soft) enforcement of appends** — the initial design; rejected on
  review: a forgotten append would degrade silently to artifact inference, making the
  journal untrustworthy exactly when it matters. Judged too weak once hooks + sole-
  routing-source were identified as viable enforcement.

## Consequences

- Resume becomes exact and cheap; executive-mode decisions and verify evidence gain a
  durable audit trail; concurrent sessions get collision *detection* (not prevention).
- The journal is machine-local: switching machines degrades to artifact inference
  (today's behavior) unless the user runs `export`/`import`. Accepted.
- The plugin grows a hook layer (`hooks/hooks.json` + scripts) and a generated sidecar
  file — more surface, but it is what makes the journal trustworthy enough to be the
  sole routing source. Hooks must fast-path no-op on projects without a sidecar.
- Residual softness is payload *quality* only (a rationale string can be lazy);
  event presence and gate ordering are mechanical. Two verified escape hatches remain
  and are accepted: a user interrupt (Ctrl-C) does not fire the `Stop` hook, and the
  harness overrides a Stop hook after 8 consecutive blocks — so gate findings must
  always be satisfiable in one round rather than relying on repeated blocking.
- Concurrency scope: multiple host-local sessions via WAL. WAL is the right tool on a
  real filesystem (`BEGIN IMMEDIATE` + `busy_timeout` beats an flock there), but it
  needs working fcntl locks and shared memory, which a container bind mount on macOS
  does not provide — opening the db from inside one fails instantly with "disk I/O
  error" (junge fleet finding, 2026-08-20). The deciding factor is the filesystem, not
  SQLite. And because WAL is a property of the file rather than the connection, that
  breakage persists after the container exits until someone runs
  `PRAGMA journal_mode=DELETE` from the host. So the journal is host-local and never
  mounted into a container: documented at the pragma itself, surfaced by `doctor`, and
  the reason a bot running a shipgate phase must do so on the host.
- Every phase skill grows a small Journal section, and `setup` becomes the blessed
  bootstrap path; `config-template.md` gains a `Journal` section.
- Schema changes now need a migration story (`meta.schema_version`, applied by
  `setup`/`doctor`).
